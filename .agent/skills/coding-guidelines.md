# General Coding Guidelines (CodeRabbit Reviews)

コードレビュー（CodeRabbit等）での頻出指摘事項を防ぐため、以下の汎用的なベストプラクティスを遵守してください。

## 1. データベース更新処理の最適化とガード
- **無駄な更新の回避**: `update` のペイロード (SET句) を構築した後、プロパティが一つもセットされていない場合 (Empty Object) は、DBの更新処理を発火させずにガード（既存データを返す、または例外送出）してください。
- **1クエリへの集約**: `UPDATE` して即座に結果を必要とする場合、`await db.update(...)` などを2回呼ぶのではなく、Drizzle 等のORMがサポートしている `.returning()` を活用し、1回のクエリ呼び出しで完結させてください。

## 2. APIエンドポイント群での認可（Authorization）の徹底
- **一貫した権限チェック**: リソースに対する更新（PUT/POST）などで権限チェック（`owner` や `admin` 限定など）を入れている場合、同じリソースを返す `GET` にも必ず同等の権限チェックが漏れていないか確認し、適用してください。

## 3. UIのフォールバック・エラーステート（Blank Screen の防止）
- **データのロード失敗時**: データの初期ロードが失敗した際、ローディングインジケーター（`isLoading === true`）が終わり、かつデータもない (`!data`) 状態になることがあります。この場合、画面が空にならないよう、必ず「読み込み失敗を示すメッセージ」および「再試行ボタン」等を表示するフォールバックUI（`{:else}` などの分岐）を明示的に実装してください。

## 4. マジックナンバーの定数化
- **バリデーションとUIの定数共有**: バリデーションロジック、エラーメッセージ、フロント側の属性 (`maxlength`)、文字数カウンターなどで利用される制限値（例: `500`）は、ハードコードによる重複を避け、ファイルのトップレベルや共通モジュールに定数 (`const MAX_INPUT_LENGTH = 500;`) として宣言後、一元的に参照するようにしてください。

## 5. 権限・表示ロジックのヘルパー化 (DRY原則)
- **権限判定の一元管理**: `roleId === 0 || roleId === 1` のような判定式であっても、複数コンポーネントで参照する場合はインラインで記述せず、専用のヘルパー関数（例: `isOwnerOrAdmin` など）として独立したファイル（`lib/auth/roles` 等）に抽出し共有してください。今後のロール変更・追加等のメンテナンスコストを削減します。
